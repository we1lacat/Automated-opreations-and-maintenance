| 1 | `### 3.5 文本三剑客` 挂在一个**空标题 `## `** 下，位置却在 `## 四、Vim` 之后，编号却属于第三章 | 内容追加时随手写了个空 `##`，导致三剑客整块（399 行）成了孤儿 | 整块搬回第三章末尾，改编号 `### 3.8`，子节 `3.5.x` → `3.8.x`，空标题删除 |

### 结果与校验

- 文件 1641 → 1631 行；章节 一~十 完整，第三章子节 3.1–3.8 连续。
- 搬移段落与改动前备份**逐行比对 `IDENTICAL: True`**（398 行零损耗，仅少掉一行有意删除的孤立 `>`）。
- 代码块围栏配平。

### 踩坑（方法层）

1. **Python 写文件把 LF 改成了 CRLF**：Windows 下 `io.open(p,'w',encoding='utf-8').write(s)` 默认把 `\n` 转成 `\r\n`，整份文件换行符被改（git 因 autocrlf 归一化看不出来，但文件已变）。
   **修法**：写完二进制回写 `b.replace(b'\r\n', b'\n')`，或一开始就 `open(p,'w',newline='\n',encoding='utf-8')`。改 markdown 后用二进制方式确认 CRLF 数量与改前一致。
2. **块搬移用行切片 + 标题断言定位**，不要硬编码行号：`find1()` 断言标题唯一出现，再切片。
3. **搬移后必须做"备份 vs 当前"逐行多重集比对**，把 missing 行逐条人工确认是有意改写，防止误删。

### 结果与校验

- 2132 行，围栏 182 条配平，CRLF=0。
- 与改前备份逐行多重集比对，182 行"差异"逐条确认均为有意重写/表格化/精简。
- 另用 **21 个关键信息点断言**复查（设备名、分区表输出、fstab 六字段、LVM 三层、扩容路线、删除顺序等），全部在位。

### 踩坑（方法层）

1. **长中文内容不要塞 heredoc**：一次失败就得整段重发。改为先 `Write` 成 `.json`（字符串数组，每行一个元素），再用短脚本读 JSON 拼接，成功率高得多。
2. **拼接时注意切片边界**：`lines[:i_a] + X + lines[i_b:]` 里若下一章标题落在被丢弃区间内，后续 `s.index('## 下一章')` 会报 substring not found——先在切片里保留边界标题，或从正确索引起接。
3. **文档体检脚本必须跟踪代码块围栏状态**，否则会把代码块内的 `# 注释` 误判成"标题前后缺空行"（`# ① xxx` 长得像 h1）。
4. 内容零丢失要**双保险**：行级多重集比对 + 关键信息点断言，缺一不可。

## 沉淀：后续维护检查清单

新增内容后按此清单过一遍，可避免同类问题复发：

1. **编号连续**：新章节是否续上号？子节是否连续？有无与既有小节重名？
2. **标题层级**：不超过四级；不用空 `##`；不用裸文本当标题。
3. **代码块**：语言标识齐全；围栏配平；块内无多余尾空格。
4. **格式**：无连续空行；标题前后有空行；表格列数一致。
5. **示例一致性**：命令用的路径、用户名、设备名在上下文里对得上。
6. **事实核对**：命令选项的含义（尤其容易混的：`fdisk` 的 `g`/`t`/`l`、`-L`/`-l`、`kill -9`/`-15`）。
7. **换行符**：改完确认 CRLF 数量未变（见第一次踩坑）。
8. **备份 + 比对**：改前 `cp` 一份，改后做行级多重集比对 + 关键点断言。
9. **排障内容归口**：新增的「避坑 / 排障 / 事故复盘」一律进 [`troubleshooting.md`](troubleshooting.md)，主笔记只留考试范围内的必要注意，并在原处留一句指向。
